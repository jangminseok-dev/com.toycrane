# toycrane 설계 — 교환소 개편·조르기·코인 주기·광고 간판·화면 문구 다듬기

- 관계: 기존 설계 `2026-10-30-toycrane-design.md` §3.3(코인 교환소)과 그래픽 개편 설계 `2026-10-31-toycrane-graphics-a-design.md` §3.11(저절로 걷기)·§3.12(교환소 방향)를 바꾼다. 4단계(`2026-10-31-toycrane-machine-stock-design.md`) 다음 작업이다.

## 1. 무엇을 왜

사용자의 친구 지형(공동 기획, 코딩은 안 함)이 써 보고 카톡에 남긴 말(2026-10-31). 사용자도 동의했다.

- "난 클로드의 저 점 디자인이 너무 싫어 — 코인이 없어요 [교환소 가기], 이렇게 '코인이 없어요'는 박스 위에 뜨고 박스 안에는 '교환소로 가기'만 있기"
- "코인 받는 중… 이거 너무 긴데 그냥 줄서기 하고 바로 못 받나 앞에서"
- "코인소 4개로 늘리고, 저렇게 가로로 말고(교환소가 너무 크고 나란히 있음), 그냥 자기네들이 알아서 줄서게 하자"
- "조르기 이런 거 해서 막 랜덤으로 10에서 50 사이 랜덤값으로 주게 하는 건 어때?"
- "토이크레인 게임센터 간판 지금 5개인가 넓게 있는데, 10개로 늘리고 문구를 광고문의1, 광고문의2 이런 식으로"

사용자가 화면을 찍어 보내며(2026-10-31): "이런 문구들도 자연스럽고 깔끔하게 개선해 줘."
- 대상: 기계 앞 버튼 '🪙5 다섯 판'·'🪙1 넣고 하기', 한 판 중 '19초 레버로 움직이고 · 잡기 버튼을 눌러요', 하강 버튼 '잡기', 유리 안 카드 '대형!'.

왜: 코인 받기가 답답하고(긴 줄·2초 대기), 교환소가 크고 몰려 있어 매장이 막혀 보인다. 조르기·코인 주기는 사람끼리 말 없이도 주고받는 재미를 만든다(기존 설계 §1의 목적: 함께 노는 트래픽). 화면 문구는 "Claude가 만든 티"가 나지 않게, 자연스럽고 짧게.

## 2. 목표 · 비목표 · 안티목표

**목표**
- 교환소를 작게, 매장 곳곳에 흩어 4곳으로. 줄 없이 창구에서 바로 받는다.
- 교환소에서 '코인 받기'(코인 5개)와 '조르기'(10~50개 무작위, 10분에 한 번) 두 가지를 고른다.
- 맵 어디서나 '조르기' 상태가 되면, 다른 사람이 와서 원하는 만큼 코인을 줄 수 있다. 조르기·주기·받기·거절 모션이 모두에게 보인다.
- 벽 광고 간판 10개('광고문의1'~'광고문의10').
- 화면 문구를 자연스럽고 깔끔하게: 가운데 점(·)으로 잇지 않고, 상태는 버튼 위에, 버튼 안에는 할 일만.

**비목표**
- 코인 카드게임장(사용자 아이디어, 나중 후보).
- 도감 화면, 인형 주고받기, 채팅.
- 진짜 돈·결제와 관련된 모든 것.

**안티목표**
- 화면이 코인 개수를 정하는 것. 조르기 금액(10~50)·쿨타임·주기 이동은 모두 서버가 정하고 확인한다.
- 쿨타임이나 줄을 위해 서버를 타이머·알람으로 깨워 두는 것(지금처럼 다음 메시지가 올 때 시각을 비교한다).
- 유료 요금제.
- 화면 문구에 가운데 점(·)으로 두 문장을 잇는 것.

## 3. 사용자가 정한 것 — [결정]

### 3.1 교환소
- 교환소가 너무 크다 → 작게.
- 두 곳이 나란히 붙어 있다 → 흩어 놓는다.
- 4곳으로 늘린다.
- 바닥에 정해진 줄 자리(옆으로 늘어선 줄)를 없애고, 사람들이 알아서 줄 선다.
- '코인 받는 중'(지금 2초)이 너무 길다 → 맨 앞이 되면 바로 받는다.
- 교환소에서 고르는 것은 두 가지: **줄 서기**(코인 5개), **조르기**(10~50개 무작위).
- **줄 없이 바로 받기**(빌더 확인 질문에 사용자가 고름, 2026-10-31): 한 사람을 처리하는 시간이 0이면 줄이 생길 일이 없으므로 서버의 줄을 없애고, 버튼 이름도 '줄 서기' 대신 **'코인 받기'**로 한다.

### 3.2 교환소 조르기 — Claude 제안을 사용자가 받아들임
- '조르기'를 누르면 3초쯤 조르는 모션을 하고, 교환소가 10~50개 중 무작위로 던져 준다.
- 한 사람은 10분에 한 번만 받는다.
- 시간이 덜 지났으면 교환소가 "조금 이따 다시 와요"라며 거절하고, 시무룩한 모션이 나온다.
- 지갑 최대를 15개에서 99개로 올린다.

### 3.3 맵에서 조르기와 주기
- 맵에서 '조르기'를 누르면 그 자리에서 계속 조르는 모션을 하는 상태가 된다. 다른 사람에게 요청을 보내는 게 아니다(승낙·거절 창 없음).
- 다른 사람이 와서 코인을 준다. **주는 사람이 몇 개 줄지 정한다.**
- 주기·받기 모션이 따로 있고, 주변 사람들에게 보인다.

### 3.4 벽 간판
- 'toycrane 게임센터' 간판을 10개로 늘리고, 문구를 '광고문의1'~'광고문의10'으로.

### 3.5 화면 문구
- 가운데 점(·)으로 잇지 않는다. 상태 문구는 버튼 위에 작게, 버튼 안에는 할 일만(예: 위 "코인이 없어요" / 버튼 "교환소 가기").
- 보내 준 화면의 문구들(기계 앞 버튼, 남은 시간·안내, 잡기 버튼, 유리 안 카드)을 자연스럽고 깔끔하게.

## 4. Claude가 정한 세부 — [내 판단]

### 4.1 교환소 코인 받기 (줄 없음)
- 창구 가까이(지금과 비슷한 약 1.5m 안 [빌더: 정확한 값])에서 '코인 받기'를 누르면 서버가 곧바로 5개를 준다. 기다림·'받는 중' 단계·순서 기억이 없다.
- 지금의 줄 구조(교환소마다 6칸 줄 자리, 줄 서기·나가기·받기 메시지, 맨 앞 시간 초과, welcome의 줄 목록, 화면의 줄 따라 걷기)는 모두 없앤다.
- 코인 받기로는 코인이 **15개 미만일 때만** 받는다(받아서 15를 넘으면 15까지).
  - 15개 이상이면 버튼 위에 "코인이 넉넉해요"를 띄우고 버튼을 흐리게 한다.
  - 15개를 넘게 모으는 길은 조르기뿐이다.
- 사람들은 창구 앞 아무 데나 서서 각자 누른다. 바닥의 발자국 표시는 '여기 서면 된다'는 장식일 뿐이다.

### 4.2 교환소 조르기
- 누르는 순간 서버가 쿨타임(마지막으로 받은 뒤 10분)을 확인하고 금액(10~50 정수, 같은 확률)을 정한다.
- 화면은 3초 조르는 모션 뒤에 결과를 보여 준다.
  - 받으면: 교환소에서 코인이 튀어나오는 연출과 "코인 N개를 받았어요!".
  - 거절이면: 버튼 위에 "N분 뒤에 다시 와요"(남은 시간을 올림한 분)와 시무룩한 모션.
- 마지막으로 받은 시각은 **게스트마다** 남긴다(D1). 다시 접속하거나 다른 탭에서도 같은 쿨타임. [빌더: 저장 위치·열]
- 지갑 99개를 넘는 만큼은 받지 않는다(99까지만).
  - 이미 99개면 조르기 버튼 위에 "코인이 가득 찼어요"를 띄우고, 쿨타임은 쓰지 않는다.
- 남용 판단(사용자에게 걱정을 말했고, 사용자가 이 방향을 받아들임): 코인이 새로 생기는 곳은 교환소뿐이라 쿨타임만 둔다. 창을 여러 개 열어 다른 게스트로 받는 것까지는 막지 않는다(로그인 없음).

### 4.3 맵 조르기
- **누를 수 있는 곳:** 기계 앞이나 교환소 가까이가 아닌 곳에서는 오른쪽 아래에 '조르기' 버튼이 늘 있다.
- **조르는 모습**
  - 그 자리에서 조르는 모션(두 손 모으고 폴짝폴짝)을 되풀이하고, 머리 위 이름표 옆에 "조르는 중"을 띄운다.
  - 매장 모두에게 보인다.
- **끝나는 때**
  - 움직이면(조이스틱·키보드·저절로 걷기) 끝난다.
  - 다시 누르거나('그만 조르기') 코인을 한 번 받아도 끝난다.
  - 접속이 끊겨도 끝난다.
- 조르는 동안에도 코인이 99개면 받을 수 없다(주는 쪽에 "코인이 가득 찼어요").

### 4.4 코인 주기
- **버튼이 뜨는 때:** 조르는 사람 가까이(약 1.5m [빌더]) 가면 '주기' 버튼이 뜬다. 버튼 위에는 "OO 님이 조르는 중".
- **개수 고르기**
  - 누르면 작은 창에서 개수를 고른다: 1개부터 '내 코인'과 '받는 사람이 더 받을 수 있는 만큼' 중 작은 수까지.
  - 기본값은 1개, 버튼(−/+)과 '최대'가 있다.
  - '주기'를 누르면 확정, 바깥을 누르면 취소.
- **서버 확인:** 서버가 다시 확인하고 한 번에 옮긴다. 확인하는 것은 다음과 같다.
  - 두 사람이 아직 가까이 있다.
  - 받는 사람이 아직 조르는 중이다.
  - 주는 사람 코인이 충분하다.
  - 받는 사람이 99를 넘지 않는다.
  - 자기 자신에게는 줄 수 없다(같은 게스트의 다른 탭 포함).
  - 실패하면 주는 쪽에 이유를 짧게 알린다("이미 그만 조르고 있어요", "코인이 모자라요" 등).
- **성공하면**
  - 주는 사람 캐릭터가 건네는 모션, 받는 사람이 기뻐하는 모션(폴짝 + 하트·코인 반짝)이 모두에게 보인다.
  - 받는 사람에게 "OO 님이 코인 N개를 줬어요", 주는 사람에게 "코인 N개를 줬어요".
  - 받는 사람의 조르기 상태가 끝난다.
- 한 판 중(기계 앞)에는 주기·조르기 버튼을 띄우지 않는다.

### 4.5 교환소 자리와 모양
- 지금 크기의 절반쯤. 창구·간판('코인 교환소')·작은 줄 표시(바닥의 발자국 몇 개 정도, 정해진 자리는 아님)만 남긴다. [빌더: 모양]
- 4곳을 매장 곳곳에 흩어 놓는다: 서로 나란히 붙지 않게, 허브 탑 둘레의 서로 다른 방향.
  - 모두 카메라 쪽(남쪽)을 보게 둔다(그래픽 설계 §3.12와 같은 이유).
  - 기계 앞자리·통로를 막지 않게 둔다.
  - [빌더: 정확한 좌표 — 만든 뒤 화면을 사용자에게 보여 준다]
- 교환소 가까이에서는 오른쪽 아래에 버튼 두 개: '코인 받기'(큰 버튼), '조르기'(작은 버튼).
- "코인이 없어요"에서 '교환소 가기'를 누르면 가장 가까운 교환소 창구 앞까지 저절로 걷는다(지금처럼 장애물을 돌아서). 줄은 저절로 서지 않는다 — 도착하면 두 버튼 중 고른다.

### 4.6 벽 광고 간판
- 매장 네 벽 위쪽에 10장을 고르게 나눠 건다(북쪽 벽은 기계 간판을 가리지 않는 높이).
- 문구는 '광고문의1'~'광고문의10'. 'toycrane' 글자는 간판 위쪽에 작게 남긴다. [빌더: 그림, 10장을 한 그림(텍스처)에 모아 그리기 호출 하나로]

### 4.7 화면 문구 다듬기 (안 — 사용자가 문서에서 확인)
원칙
- 가운데 점(·) 금지.
- 상태는 버튼 위 작은 글(새 "상태 줄"), 버튼 안에는 할 일만.
- 코인 값은 글자 앞에 붙이지 않고 버튼 오른쪽의 작은 코인 배지(🪙 1)로.

| 지금 | 바꿀 문구 |
|---|---|
| 버튼 '🪙1 넣고 하기' | 버튼 '한 판 하기' + 배지 '🪙 1' |
| 버튼 '🪙5 다섯 판' | 버튼 '다섯 판 하기' + 배지 '🪙 5' (코인이 모자라면 '세 판 하기' + '🪙 3' 등) |
| 판 사이 '🪙1 한 번 더' | 버튼 '한 판 더' + 배지 '🪙 1' |
| 판 사이 '🪙5 다섯 판 더' | 버튼 '다섯 판 더' + 배지 '🪙 5' |
| 버튼 '코인이 없어요 · 교환소로' | 상태 줄 '코인이 없어요' / 버튼 '교환소 가기' |
| 알림 '코인이 없어요 · 교환소에서 받아요' | 알림 '코인이 없어요. 교환소에서 받을 수 있어요' |
| 상태 '구경 중 · 다른 사람이 하는 중' | 상태 줄 '다른 사람이 하고 있어요' |
| 상태 '이어서 하기 · 12초' | 상태 줄 '12초 안에 이어서 할 수 있어요' |
| 상태 '다음 판 · 2/5판' | 상태 줄 '곧 두 번째 판이 시작돼요' |
| 상태 '줄 서는 중 · N번째', '코인 받는 중…' | 없앤다(줄이 없어짐) |
| 알약 '19초 레버로 움직이고 · 잡기 버튼을 눌러요' | 알약에는 남은 시간만 크게('19초'), 여러 판이면 옆에 작은 '2/5판'. 안내('레버로 집게를 옮기고 잡기 버튼을 눌러요')는 처음 3초만 알약 아래에 작게 떴다 사라진다 — 뒷판 모니터를 가리지 않게 |
| 하강 버튼 '잡기' + 화살표 | 글씨가 윗면 밖으로 나가지 않게 줄이고 가운데로. 화살표는 글씨 아래 작게 |
| 유리 안 카드 'NEW!', '잘 뽑혀요♪', '대형!', '인기 1위', '한정', '신상' | '새로 왔어요', '잘 잡혀요', '오늘의 추천', '인기 1위', '한정판', '행운 기계' — 영어·특수기호를 빼고, 간판 글꼴로 가운데 맞춰 단정하게 |

**곁들임:** 집게가 상품 구멍 위(시작 자리)에 있는 동안은 겨냥 고리를 숨긴다. 사용자 화면에서 레버 공 뒤에 분홍 고리가 걸쳐 보인다(인형이 없는 곳이라 고리가 필요 없다).

### 4.7.1 희귀가 든 기계 표시 (4단계 반짝임을 바꿈)
- 문제: 사용자(2026-10-31)가 "이런 효과가 있는 거 봤는데, 똥파리나 이상한 게 돌아다니는 줄 알았어"라고 했다. 간판 위를 도는 작은 분홍 팔면체가 날벌레처럼 보이고, 무엇인지 알 수 없다.
- 바꿀 것
  - 간판 위에 작은 이름표가 살짝 떠서 천천히 위아래로 흔들린다.
    - 희귀: 분홍 '★ 희귀'.
    - 황금: 금색 '★★ 황금'(조금 크게).
  - 이름표 둘레에 네 갈래 별 모양 반짝이 2~3개가 제자리에서 커졌다 작아지며 반짝인다(돌아다니지 않는다).
  - 글자로 무엇인지 알 수 있게 한다.
- 행마다 한 덩어리로 그려 그리기 호출을 늘리지 않는다. [빌더: 이름표 그림·크기]

### 4.7.2 한 판 중 앞을 가리는 다른 사람 — [결정] 고쳐야 함, 방법은 [내 판단]
- 사용자(2026-10-31, 화면 첨부): "플레이하고 있을 때 다른 유저가 내 앞에 서면 게임이 보이지 않아 방해받는데 이것도 개선해야 해."
- 내 화면에서만: 내가 기계 앞 카메라로 하는 동안(한 판·판 사이·결과 연출), 카메라와 그 기계 사이(기계 폭보다 조금 넓고 카메라까지의 깊이)에 들어온 다른 캐릭터는 이름표와 함께 거의 투명하게(약 15%) 흐린다.
- 그 자리를 벗어나거나 내가 기계에서 일어나면 0.2초쯤에 걸쳐 원래대로 돌아온다.
- 다른 사람 화면에서는 그대로 보인다(서버·다른 화면은 바뀌지 않음).
- 그리기 호출을 늘리지 않는다. [빌더: 흐리는 방법 — 재질 복제·숨기기 등]

### 4.8 모션
새 모션 네 가지. 지금 아바타 모션(쾅·두근·털썩)과 같은 만화풍이고 짧다. [빌더: 동작 세부]
- 조르기(되풀이): 두 손을 모으고 폴짝폴짝, 고개 갸웃.
- 주기: 상대 쪽으로 몸을 돌려 코인을 건네는 팔 동작 + 코인 하나가 날아간다.
- 받기 기쁨: 폴짝 뛰며 하트·코인 반짝.
- 거절당함(교환소): 어깨가 축 처지고 고개를 떨군다.

## 5. 제약
- 무료만, 유료 전환 금지. 서버를 타이머·알람으로 깨워 두지 않는다(쿨타임·줄은 다음 메시지가 올 때 시각 비교).
- 코인 개수·무작위 금액·쿨타임·주기 확인은 서버가 한다. 화면은 받은 대로 보여 준다.
- 지갑은 D1 게스트별 그대로. 주기는 두 사람 지갑을 한 번에(원자적으로) 바꾼다.
- 헥사고날·슬라이스 1:1·import-linter(기존과 같음).
- 일본어 글자 금지. 화면 문구는 `copy.ts` 한 곳에 두고 검사한다.
- 가운데 점(·) 금지 — 문구 검사에 함께 넣는다.
- 휴대폰 그리기 호출이 지금(`client/e2e/perf-stock.json`: 걷기 370·기계 앞 152)보다 늘지 않는다.
- 메시지 형식이 바뀌므로 프로토콜 버전을 올린다(열려 있던 화면은 저절로 한 번 새로고침).
- 옛 줄(교환소마다 6칸 줄 자리, 줄 메시지, '코인 받는 중' 단계)은 모두 없앤다.

## 6. 빌더에게 맡기는 것
- 교환소 4곳의 정확한 좌표·모양, 장애물 상자, 저절로 걷기 길.
- 간판 10장의 자리와 그림.
- 모션 동작 세부, 코인 튀어나오는 연출.
- 쿨타임 저장 위치(D1 열/표), 메시지 형식.
- 개수 고르는 창의 모양(리퀴드 글라스 스타일 안에서).

## 7. 성공 기준
- 교환소 4곳이 작고 흩어져 있다. '코인 받기'를 누르면 즉시 코인 5개(15 미만일 때).
- 교환소 '조르기'는 10~50개를 주고, 10분 안에 다시 누르면 거절 모션과 남은 분이 뜬다(서버 테스트로 확인).
- 맵에서 조르는 사람에게 다른 사람이 원하는 개수를 주면 두 지갑이 정확히 바뀌고, 주기·기쁨 모션이 모두에게 보인다.
- 지갑 최대 99. 99를 넘게 받거나 줄 수 없다.
- 벽 간판 10장 '광고문의1'~'광고문의10'.
- 화면 어디에도 가운데 점(·)으로 이은 문구가 없고, §4.7 문구로 바뀌어 있다.
- 희귀가 든 기계 위에는 '★ 희귀'/'★★ 황금' 이름표와 제자리 반짝이가 뜬다(날벌레처럼 도는 점이 없다).
- 한 판 하는 동안 다른 사람이 카메라와 기계 사이에 서도 내 화면에서는 거의 투명해져 게임이 가려지지 않는다.
- 휴대폰 그리기 호출이 늘지 않는다.
