# toycrane 설계 — 같이 노는 온라인 인형뽑기방

- 작성: 2026-10-30 (브레인스토밍 2회 세션 결과)
- **승인: 2026-10-30** — 사용자가 [내 판단] 항목을 포함해 문서 전체를 승인("이대로 설계 문서 진행하자")
- 표기: **[결정]** = 사용자가 정한 것, **[내 판단]** = 브레인스토밍 중 내가 정한 것(사용자 확인 전·바꿔도 됨), **[빌더]** = 만드는 사람이 정할 것

---

## 1. 무엇을 왜 만드나

친구(지형)와 같이 만드는 **웹 3D 온라인 인형뽑기방**. 실제 사람들이 캐릭터로 매장 안을 돌아다니고, 남이 뽑는 걸 구경하고, 희귀 인형이 나오면 매장 전체가 들썩이는 "같이 있는 느낌"이 핵심이다.

- 레퍼런스: 산사(sansatemple.com) — 시중 서비스. three.js 화면 + 웹소켓으로 같은 방 사람들이 보이는 구조와 "방마다 정원" 개념을 참고. (우리 프로젝트 아님)
- **[결정] 목적은 수익이 아니라 트래픽.** 성공 = 사람이 많이 오고, 다시 온다.
- **[결정] 현금 결제 없음.** 코인은 무료로 받는다. 그래서 확률형 아이템 규제 대상이 아니다. 코인 판매를 붙이는 순간 규제를 다시 검토해야 한다.

## 2. 목표 · 비목표 · 안티목표

**목표**
- 링크 하나 누르면 로그인 없이 바로 매장에 들어와 뽑기를 해볼 수 있다.
- 50명이 한 매장에서 서로 보이고, 희귀 당첨이 모두에게 보여서 "나도 해볼까"를 만든다.
- 도감 세트·오늘의 기계·자랑 카드로 다시 오고, 퍼뜨리게 만든다.

**비목표 (1차에 안 함)**
- 로그인·회원가입, 결제, 보이스 채팅(악용 우려로 나중), 진짜 물리 시뮬레이션, 여러 층·여러 방 구조, 네이티브 앱.
- **[내 판단]** 자유 텍스트 채팅도 1차 제외. 로그인이 없어 악용을 막기 어렵고, 반응은 리액션 버튼으로 대신한다.

**안티목표 (돌아가도 이러면 실패)**
- 유료 요금제로 넘어가는 것. **[결정]** 무료 한도를 넘으면 유료 전환이 아니라 "만석"으로 기다리게 한다.
- 기존 캐릭터·브랜드를 베끼는 것. 인형은 전부 오리지널, 매장 레퍼런스 사진 속 상표명(예: 기계 위 브랜드 로고)도 쓰지 않는다.
- 결과를 클라이언트가 정하는 것. 확률·코인·도감은 반드시 서버가 판정한다(조작 방지, 화면 동기화).
- 밝은 파스텔 방. **[결정]** 사용자가 "뽑기방 같지 않다"고 거절한 방향. (2026-10-31: 밝되 원색 기계가 빽빽한 일본 게임센터로 바뀜 — 그래픽 개편 설계 §2)

## 3. 매장 (맵)

### 3.1 구조 — [결정]
- **큰 정사각형 1층 매장 하나.** 층이나 방으로 나누지 않고, 그 안에 **미니 · 피규어 · 큰인형 구역이 따로** 있다.
- **가운데 광장형**: 이벤트·전광판·코인·도감을 **가운데 허브에 균형 있게** 모으고, **스폰도 가운데**.
- 정원 **약 50명**. 차면 같은 매장을 하나 더 연다(1번 매장, 2번 매장 …). 무료 예산이 다 차면 더 열지 않고 "만석".

### 3.2 배치 — [내 판단] (사용자가 배치도를 보고 큰 틀은 승인, 수치는 내 판단)
참고 배치도: `.superpowers/brainstorm/63849-1793340653/content/map-layout-v3.html`

```
┌──────────────────────── 26m ────────────────────────┐
│              큰인형 구역 (위쪽 띠 전체)               │
│     벽 따라 한 줄 + 등 맞댄 섬 2줄                   │
├──────────┬──────── 가운데 허브 10m ───────┬──────────┤
│          │ 코인 교환소①        도감 NPC    │          │
│  미니    │        (스폰 링)                │  피규어   │
│  구역    │      4면 전광판 탑              │  구역     │
│ (왼쪽    │ 이벤트(오늘의 기계)  코인 교환소② │ (오른쪽   │
│  ㄴ자)   ├───────────┐ ┌──────────────────┤  ㄴ자)    │
│          │           │ │                  │          │
└──────────┴───────────┘ └──────────────────┴──────────┘
```
- 매장 26m × 26m. 허브 10m × 10m.
- 허브 한가운데: **4면 전광판 탑**, 그 둘레가 **스폰 링**(접속하면 전광판 앞에서 시작).
- 허브 대각선 네 귀퉁이: **코인 교환소 2곳(서로 마주 봄) · 도감 NPC · 이벤트(오늘의 기계·피버)**.
- 허브에서 위·왼쪽·오른쪽·아래 네 갈래 길이 각 구역으로 이어진다.
- 큰인형 = 위쪽 띠(기계가 커서 가장 넓게), 미니 = 왼쪽 ㄴ자(2단 미니 기계 벽), 피규어 = 오른쪽 ㄴ자.
- 입구 없음(스폰이 가운데).
- 기계 대수·통로 폭은 [빌더]가 50명이 붐비지만 답답하지 않게 조정. 시제품 기준: 22×18m에 큰 기계 40대 + 미니 28칸 + 50명이 적당했다.

### 3.3 허브 시설
- **전광판 탑 (4면)** — [결정] 평소엔 "오늘의 기계 · 피버 타임" 안내, 희귀가 나오면 "○○ 님이 ★별빛 토끼를 뽑았어요" 를 매장 전체에 띄운다.
- **코인 교환소 2곳** — [결정] 줄 서서 무료 코인을 받는다(전당포 같은 창살 카운터 느낌, 줄 서기 차단봉). 1판 = 1코인.
  - [내 판단] 줄은 장식이 아니라 **서버가 관리하는 실제 줄**. 캐릭터가 차단봉 안에 차례로 서고, 창구에서 한 사람당 짧게(2초 안팎) 처리한다. 줄에서 벗어나면 차례가 빠진다.
  - [빌더] 한 번에 몇 개 주는지, 다시 받기까지 쿨타임.
- **도감 NPC** — [결정] 누르면 내 도감 화면이 펼쳐진다. NPC 뒤에 **희귀만 올린 작은 진열장**(도전 욕구용, 천천히 회전).
- **이벤트 자리** — [내 판단] "오늘의 기계"(그날 잘 뽑히는 기계)를 무대 위에 두고 피버 타임 안내를 겸한다. 50명이 한 대를 두고 싸우지 않게 **같은 기계를 여러 대(예: 4대)** 무대에 둔다.

## 4. 분위기 · 그래픽

### 4.1 그래픽 방식 — [결정]
> 2026-10-31: 그래픽 개편 설계 `2026-10-31-toycrane-graphics-a-design.md`가 이 절과 §4.2를 바꾼다(밝은 일본 게임센터 + 만화 고급화).
- 3D 모델을 만들 사람이 없으므로 **코드로 만드는 장난감 스타일**: 구·캡슐·상자 같은 도형 조합 + 3단 툰 셰이딩 + 외곽선. three.js.
- 캐릭터는 **손이 몸에서 떠 있는** 동글이 스타일, 모션도 코드(트윈)로.
- 참고 시제품(버리는 코드, 동작·그림체 기준): `.superpowers/brainstorm/63849-1793340653/content/spike-arcade-big-v3.html`

### 4.2 매장 분위기 고증 — [결정] (친구가 준 실제 매장 사진 기준)
- 어두운 천장(거의 검은 보라) + **분홍 네온 줄**, 매장 전체가 보랏빛으로 물든 조명.
- 바닥은 **회색 대리석**을 큰 판으로 쫙.
- 기계는 **흰 몸통 + 파란 LED**(상품 출구 테두리·바닥 띠·조작대 아래), 위 간판에 전구와 **번호판(A-1 …)**, 기계 위 **체크무늬 삼각 깃발**.
- 실제 크레인 기계 구조: 아래 캐비닛(코인 투입구·카드 단말기·조작대·상품 출구), 유리 칸(펠트 바닥·**상품 구멍과 투명 아크릴 가림막**·뒷판 그림·실내등), 위 간판.
- 미니 구역은 **2단으로 쌓은 미니 기계 벽**. 곳곳에 아이용 발판.

### 4.3 화면 UI — [결정] (2026-10-31, 1단계 실배포 확인 중)
- 화면 위 UI(조이스틱·카드·버튼·상태 표시·이후 도감·코인 등)는 **아이폰 리퀴드 글라스 느낌**: 뒤가 흐리게 비치는 반투명 유리 + 위쪽 반사광 + 둥근 모서리, 강조는 분홍 유리.
- 조작은 숨기지 않는다: 휴대폰 조이스틱은 처음부터 왼쪽 아래에 보인다(실제 휴대폰에서 숨은 조이스틱을 못 찾음).

## 5. 뽑기

### 5.1 조작 — [결정] A안
- 1코인 넣기 → 제한시간 안에 **조이스틱으로 집게를 자유롭게 이동** → **내리기**.
- 집게가 인형의 **어느 부위 위에 있었는지(머리·몸통·팔·빈 곳)**에 따라 성공 확률이 달라진다.
- **최종 결과는 서버 확률**로 결정. 진짜 물리 시뮬은 안 한다.

### 5.2 기계 차지 — [내 판단]
- **기계 한 대 = 한 번에 한 사람.** 먼저 코인을 넣은 사람이 그 판 동안 기계를 잠그고, 다른 사람은 뒤에서 구경(+리액션)한다. 판이 끝나면(또는 일정 시간 입력이 없으면) 풀린다.
- 기계 앞 대기 줄은 1차에 만들지 않는다. 인기 기계는 "오늘의 기계 여러 대"와 피버로 분산한다.

### 5.3 판정 흐름
1. 클라이언트: 내리기 순간의 집게 위치를 서버에 보낸다.
2. 서버: 그 위치에 있던 인형·부위 → **부위별 확률표 × 인형 희귀도 × 보정(오늘의 기계·피버·근성 게이지)** 로 결과 결정.
3. 결과: **성공 / 들었다가 놓침 / 헛잡음** + 잡은 부위 + 뽑은 인형.
4. 모든 클라이언트가 결과에 맞는 **미리 만든 모션**을 재생("머리 잡고 올리다 미끄러짐" 등).
- [빌더] 기계 안 인형 배치를 서버가 정해 모두에게 같게 보이게 할지, 부위 판정 영역을 인형마다 어떻게 둘지, 확률 수치.

### 5.4 당첨 연출 — [결정]
- **풀스크린 당첨 카드는 본인만** 본다.
- 주변 사람에게는: 그 기계가 반짝이고, 당첨음, 캐릭터가 **머리 위로 번쩍 들어 보이는** 모션.
- **희귀는 모두에게**: 번쩍 들기 + 기계 금색 반짝임 + **전광판 알림**(닉네임 포함). 목적은 "저 사람 희귀 뽑았네, 나도 해볼까".

### 5.5 모션 — [결정] 1차 8종
"줍고 → 들어 보이고 → 가방에 넣는" 흐름의 느낌만 가져오고 동작은 우리 고유의 것으로.
- 기계 작동(주변에도 보임): **코인 넣기**(딸랑) · **조이스틱**(스틱 따라 몸 기울기) · **내리기 쾅**(손바닥으로 버튼) · **두근두근**(두 손 모으고 발 동동)
- 결과: **꺼내기**(배출구에 손) · **번쩍 들기**(머리 위로) · **가방에 쏙**(등 가방) · **털썩**(실패, 어깨 축 + 먹구름)
- 시제품에 8종 모두 구현돼 있음(기준으로 삼을 것).

## 6. 인형과 도감

### 6.1 인형 — [결정]
- 전부 **오리지널**(저작권). 도형 조합 장난감 스타일.
- **세트로 묶는다**: 시제품 기준 **4세트 × (일반 6 + 희귀 1) = 28종**. (세트 방식은 승인, 세트 이름·생김새는 [내 판단])

| 세트 | 일반 6종 | 희귀 |
|---|---|---|
| 말랑 동물 | 토끼, 곰돌이, 고양이, 강아지, 판다, 햄찌 | ★별빛 토끼 |
| 숲속 친구들 | 여우, 너구리, 다람쥐, 부엉이, 아기사슴, 고슴도치 | ★황금 여우 |
| 물가 친구들 | 펭귄, 개구리, 오리, 물범, 문어, 고래 | ★진주 펭귄 |
| 꿈동산 친구들 | 병아리, 꿀꿀이, 양, 젖소, 공룡, 유니콘 | ★무지개 공룡 |

- 희귀는 왕관 + 반짝이 + 특수 재질(별무늬·금색·진주·무지개).
- 사용자는 인형 종류가 **많을수록 좋다**고 두 번 요청했다. 세트를 늘릴 수 있는 구조로.
- [내 판단] 인형은 3D 모델러 없이 **개발자(또는 Claude)가 코드로 만든다**(§4.1). 그래서:
  - 생김새는 클라이언트에 인형별 코드 모듈로 둔다.
  - 이름·세트·희귀도·구역·부위 판정 영역 같은 **목록 정보는 데이터 파일 한 곳**에 두고, TypeScript 클라이언트와 파이썬 서버가 같은 파일을 읽는다.
- [내 판단] **한정 인형**은 도감에서 세트와 별도인 "한정" 칸에 둔다. 세트 완성 조건에는 넣지 않아서, 늦게 온 사람도 세트는 완성할 수 있다. 한정은 나중에 다시 돌아올 수 있다.

### 6.2 구역별 상품
- [결정] **큰인형 · 미니 · 피규어 모두 같은 28종 캐릭터**로, 각각 "이쁘고 귀엽게" 따로 다듬는다.
- **큰인형 구역**: 위 인형 세트를 큰 크기로.
- **미니 구역** — [결정] 같은 인형을 작게. [내 판단] 모양: **머리가 큰 2등신**(몸 0.78배·머리 1.16배) + 머리 위 **키링 고리와 볼 체인**.
- **피규어 구역** — [결정] 같은 28종. ## 9. 서버와 호스팅

### 9.1 호스팅 — [결정] 무료, 온프레미스 안 함
- **[내 판단] Cloudflare 무료 요금제** (사용자 동의):
  - 화면: **Cloudflare Pages**(정적 파일).
  - 실시간: **Workers + Durable Objects**. **매장 하나 = Durable Object 하나**(50명 위치 동기화, 뽑기 판정, 게이지).
  - 저장: **D1**(게스트·코인·가방·도감·이어하기 코드).
- 무료 한도(2026-10 확인, 공식 문서로 다시 확인할 것): Durable Objects 요청 하루 10만 건, 수신 웹소켓 메시지는 20개 = 1건, 넘으면 그날은 오류. 무료 계정 DO 저장소 총 5GB, SQLite 기반 DO만 가능.
- **[결정] 한도를 넘을 만큼 몰리면 "만석".** 유료 전환 금지.
  - [내 판단] 하루 사용량을 서버가 직접 세서(예: 전역 카운터) 한도에 가까워지면 새 매장을 열지 않고, 새 접속은 만석 화면으로.
  - [내 판단] **이미 안에 있는 사람은 내보내지 않는다.** 그래서 한도에 닿기 전에 여유분을 남기고 입장을 막는다. 한도에 실제로 닿으면 모든 요청이 실패하기 때문이다.
  - 무료 한도는 매일 00:00 UTC = **한국 시간 오전 9시**에 초기화된다.
  - **[결정] 하루에 나눠 쓴다.** 먼저 온 순서대로 다 쓰지 않고, 시간마다 쓸 양을 정해 저녁 시간대까지 열려 있게 한다. [빌더] 시간당 배분 방식(균등, 저녁 가중, 남은 양 이월 등).
  - 요청 수 말고 **사용 시간(duration) 무료 한도**도 있다. 하루 약 13,000 GB-s로 알려져 있고 공식 문서로 다시 확인해야 한다. 50명이 붐비는 매장은 잘 잠들지 않아서 이쪽이 먼저 찰 수 있으니 같이 센다.
- 메시지 아끼기가 곧 수용 인원이다 — [내 판단] 위치를 주기적으로 보내지 말고 **입력이 바뀔 때만**(방향 시작·멈춤) 보내고 나머지는 클라이언트 보간. 웹소켓 **hibernation**을 써서 조용할 때 사용 시간 요금이 안 나가게.
  - 계산: 위치를 계속 보내면 꽉 찬 매장 하나가 몇 시간 만에 하루 한도를 다 쓰고, 변화 때만 보내면 꽉 찬 매장 하나가 하루 대부분을 돌 수 있다.
- Cloudflare 계정은 아직 없음. 구현 첫 단계에서 무료 계정을 만든다.

### 9.2 서버 언어 — [결정] 파이썬 (Python Workers)
- 2026-10-30 시험(`spikes/py-do-hibernation/`, 버리는 코드)으로 로컬(wrangler dev, workerd)에서 확인:
  - 파이썬 Durable Object가 **웹소켓 hibernation**으로 동작. 15초 쉬면 인스턴스가 새로 만들어지는데(메모리 초기화) **접속 2개는 유지**되고 브로드캐스트 정상.
  - 핸들러 이름은 JavaScript식: `self.ctx.acceptWebSocket(server)`, `self.ctx.getWebSockets()`, `async def webSocketMessage(self, ws, message)`, `async def webSocketClose(self, ws, code, reason, wasClean)`. 응답은 `Response(None, status=101, web_socket=client)`, 소켓 쌍은 `from js import WebSocketPair` → `WebSocketPair.new().object_values()`.
  - 닫기 코드 1005(코드 없음)·1006은 그대로 돌려보내면 오류 → 1000으로 바꿔 닫는다.
  - `workers` SDK가 외부 패키지(workers-py ≥ 1.9)로 바뀜. 정식 도구는 **uv + pywrangler**(`uv run pywrangler dev/deploy`). 시험은 `disable_python_external_sdk` 플래그로 내장판을 썼다.
  - 서버 런타임 파이썬은 **3.14**(Pyodide). 로컬 테스트용 파이썬도 맞춰야 한다(이 맥 기본은 3.9 → uv로 관리).
- **잠들면 메모리가 날아간다** → 매장 상태(게이지 등)는 DO 저장소에, 접속별 정보는 웹소켓 attachment(최대 16KB)에 둔다. 깨어날 때 생성자에서 복구.
- 코드를 배포하면 모든 매장의 웹소켓이 끊긴다(Cloudflare 동작). 재접속 처리 필요.
- 아직 확인 안 됨: **실제 무료 계정 배포**(구현 첫 단계), Python Worker의 메모리 한도 안에서 50명 매장이 버티는지.
